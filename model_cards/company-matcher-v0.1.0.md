# Model Card: company-matcher-v0.1.0

- **发布日期**：2026-08-24
- **对应 GitHub Release**：`v0.1.0`（附件见 Release 页面：`model.joblib` / `manifest.json` / `SHA256SUMS`）
- **对应内部实验代号**：`classic-lr-v6`（见 `MODEL_CHANGELOG.md` 的版本对照表）
- **对应训练记录**：[`experiments/2026-08-24-frozen-test-and-privacy-fix/`](../experiments/2026-08-24-frozen-test-and-privacy-fix/)
- **状态**：`experimental`——Precision 未达到项目自定的 98% 长期目标（当前 0.907），发布方决定
  98% 是持续优化方向而不是这次发布的硬门槛，见下方"已知局限"。

## 这个模型做什么

输入一条社交媒体/新闻消息文本 + 一个候选公司（来自规则匹配召回），输出这个候选是否真的在说这家公司
（二分类：真实提及 / 通用词撞库等假阳性）。不是"从任意文本里识别股票"的通用分类器——上游已经用正则
做过一轮候选召回，这个模型只做消歧。

## 训练数据

不随代码/模型公开（原始消息含第三方社交媒体内容，涉及版权/隐私，见仓库根目录 README 的说明）。
`examples/synthetic_messages.jsonl` 提供了一批可复现的合成示例，覆盖已知的典型假阳性/真阳性模式。

训练集/验证集/测试集按时间切分，并做了近重复内容聚类去重（同一条转发/复制粘贴文案换个消息 id
不会同时出现在训练集和测试集里），细节见训练记录。测试集从 2026-08-24 起永久冻结，未来版本
沿用同一批消息 id 做比较，不再每次重新切分。

**送进特征提取前的文本会先脱敏**（`src/text_sanitize.py` 的 `sanitize_message_text()`，训练和线上
推理调用同一个函数）：URL、邮箱、长数字ID 替换成占位符；`@handle` 只有在跟已注册的公司代码/别名/
品牌名精确匹配时才换成公司名（保留信号），否则一律替换成通用的 `[HANDLE]` 占位符。候选召回（规则层）
用的仍是脱敏前的原文，脱敏只影响分类器看到的特征文本。

## 指标（冻结测试集）

| 指标 | 数值 |
| --- | --- |
| Precision | 0.907 |
| Recall | 0.975 |
| F1 | 0.940 |
| 阈值 | 0.6396 |

对照：候选生成阶段（规则+上游）单独当分类器的 baseline F1 约 0.42；上一个发布过的内部基线
`classic-lr-v3`（在同一份修复后的冻结测试集上重新打分）是 Precision 0.868 / Recall 0.982 / F1 0.921——
这个模型相对它是明确提升，但 Precision 还没到项目自定的 98% 目标线。

**发布前有一版指标更高**（`classic-lr-v5`，Precision 0.938）但从未发布：隐私复查发现词表里还留有
可识别到具体个人的真实 Twitter 用户名片段，加上文本脱敏、重训成这一版后 Precision 降到了 0.907——
这是隐私修复的真实代价，不是训练波动，详见训练记录。

## 已知局限

- **Precision 未达 98% 长期目标**：0.907，意味着大约每11个模型判定为"真实提及"的候选里，
  有1个其实是通用词撞库等假阳性（`Strategy`/`NOW`/`Oracle`/`BB` 等，详见 README 里链接的
  假阳性模式记录）。98% 是持续优化方向，不是这次发布的门槛。
- **候选召回率本身有上限**：这个模型只对上游规则已经召回的候选做二次判断，规则层召回率本身
  （约 97.5%）会独立限制端到端整体正确率上限，这个模型没法把漏掉的候选找回来。
- **训练语料以英文/中文社交媒体与新闻为主**：其他语言、其他文体（比如财报原文、监管文件）
  上的表现没有专门验证过。
- **脱敏是精确匹配，不是语义理解**：`@handle` 白名单靠字符串精确匹配公司注册的代码/别名/品牌，
  一个真实的官方账号如果没有出现在公司注册信息里就不会被识别、会被当成普通 handle 脱敏掉；
  反过来，脱敏也不会误判——只有精确匹配才映射成公司名，类似 `@Tesla_Teslaway` 这种子串包含
  但不精确匹配的粉丝账号会被正确脱敏成占位符，不会泄漏成公司名。
- **TF-IDF 词表仍会包含训练语料里出现过的部分真实内容**（这是词袋模型的固有特性）：发布前的
  隐私复查确认了整句中文泄漏（=0）、URL（=0）、邮箱（=0）、已知真实用户名（=0）；词表里保留的
  长数字串只有真实注册的股票代码（比如 A 股 `688825`），以及 `@X` 这类平台/品牌名（因为长度
  规则里单字符 handle 不做脱敏，这类是公司名不是个人信息）。

## 加载方式

```python
import joblib

bundle = joblib.load("model.joblib")
# 具体字段见 src/semantic_matcher.py 里 SemanticMatcher 的加载逻辑
# bundle 的 key: word_vectorizer / char_vectorizer / classifier / use_structured / structured_feature_names
# 推理前记得用 src/text_sanitize.py 的 sanitize_message_text() 处理输入文本，
# 跟训练时用的是同一个函数——不脱敏直接喂原文会跟训练时的特征分布不一致。
```

推荐阈值 **0.6396**（在验证集上选定，Precision=0.981，Recall=0.978；冻结测试集上的实际表现见上表）。
