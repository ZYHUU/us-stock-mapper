# 2026-09-01: CrowdStrike候选层召回修复（v0.1.1发布）

## 背景

内部工作区曾经尝试过一轮更大范围的候选层（规则层）修复，目标是同时覆盖
5家公司的裸公司名/简称漏召回问题：CrowdStrike（`CRWD`）、Nebius
（`NBIS`）、Marvell（`MRVL`）、JPMorgan（`JPM`俗称"小摩"）、Alibaba
（`BABA`裸"阿里"）。这5家公司的候选层召回缺口，最初是在跟第三方候选
服务（newsocket）做同候选比较时发现的：这些公司在 securities 主数据里
只注册了完整法定名称（比如"CrowdStrike Holdings, Inc."），没有覆盖
真实文本里更常见的裸公司名/俗称写法，导致候选层直接漏召回，分类器
根本没有机会打分。

按项目一贯的验收纪律（冻结数据在先、独立双人盲标+仲裁、预注册统计
门槛、置信区间而非单点估计）逐项验证后，**最终只有CrowdStrike一项
经得住检验，是本次唯一发布的修复**：

- **Nebius**：召回率提升方向正确，但精确率测出真实下降（配对bootstrap
  置信区间下界−5.70个百分点，明确低于预注册的−2个百分点非劣界值，
  不是样本不足导致的噪声）。根因是裸"Nebius"这个词在非正式语境（个人
  评论、无差异化多股票清单、转发同一段通用话术）里比股票代码或公司
  全称更容易被随意提及，新别名带来的误触发比修复前更多。
- **Marvell、Alibaba**：召回率点估计为正，但置信区间下界没有过0——
  证据方向对但强度不够，不是"没有效果"，是"目前样本量下无法排除噪声"。
- **JPMorgan**：测试样本里修复前的基线召回率已经是100%，没有可以
  提升的空间，这条门槛在这家公司身上结构性地无法满足。

这四项都保留在内部改进清单，本次不发布，避免夹带未经验证或已知有
代价的改动。**本报告只覆盖成功发布的CrowdStrike修复。**

## 改了什么

`data/companies.csv` 新增一行：

```
crowdstrike,CrowdStrike,NASDAQ,CRWD,CrowdStrike,,
```

不涉及分类模型（`classic-lr-v6`原样保留）、不涉及其他任何公司的候选层
规则、不涉及线上部署脚本以外的任何代码路径。

## 定向测试结果

用与修复前完全相同的分类模型、只切换候选层规则（修复前/修复后两个
快照），在独立盲标确认的CrowdStrike专项测试集上重放比对：

| 指标 | 修复前 | 修复后 | 差值 | 置信区间（配对bootstrap，5000次重采样，单侧95%） |
| --- | ---: | ---: | ---: | --- |
| Precision | 0.805 | 0.837 | +3.18pt | 下界 +1.11pt（≥ 预注册的−2pt非劣界值） |
| Recall | 0.786 | 0.976 | +19.0pt | 下界 +9.52pt（> 0，优效性检验通过） |

测试集通过独立文本关键词初筛（跟候选层/分类器/第三方服务的任何输出
无关）圈定候选池，再走两轮相互独立的人工判断+分歧仲裁得到最终真值，
冻结数据在先、任何模型打分在后。

## 上线观察

小范围发布后，预先锁定五条验收条件（发布前定死，观察期内不因为看到
数据而调整）：

| 条件 | 门槛 | 实测 |
| --- | --- | --- |
| 自然消息样本量 | ≥1,000条 | 8,007条 |
| 独立确认的真实CrowdStrike案例 | ≥10条 | 11条（候选池18条，两批独立判断） |
| 非CrowdStrike文本误触发`NASDAQ:CRWD` | =0 | 0 |
| 其他公司候选识别结果相对修复前基线的差异 | =0 | 0（同一文本分别喂给修复前/后两个快照重放对比，不依赖数据库历史字段） |
| 生产进程异常 | 无 | 全程无重启、无相关报错 |

五条全部满足后，此次修复由观察期转为稳定发布。

## 结论 / 后续

- 这是一次范围明确的候选层定向修复，不是分类模型升级，也不是"整体
  识别能力提升"。
- Nebius、Marvell、JPMorgan、Alibaba的候选层修复继续留在内部改进
  清单，不因为CrowdStrike这次发布顺带发布——每一项后续如果要发布，
  都需要用全新数据重新走一遍同样的独立验收流程，不能复用这一轮已经
  用过的评估数据。
